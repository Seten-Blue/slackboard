Solicitudes de Amistad

Documentacion completa del sistema de amistad en SlackBoard

Que es

SlackBoard permite a los usuarios conectarse entre si mediante solicitudes de amistad. Las amistades son mutuales: ambas partes deben aceptar la solicitud para que se establezca la conexion. Esto garantiza que ambos usuarios estan de acuerdo en comunicarse.

Estados de una solicitud

Pendiente

El usuario A envio una solicitud. El usuario B aun no respondio. La solicitud puede ser:

  • Aceptada por el receptor
  • Rechazada por el receptor
  • Cancelada por cualquiera de los dos

Aceptada

Ambos usuarios son ahora amigos. Pueden:

  • Verse mutuamente en la lista de amigos
  • Recibir notificaciones de actividad
  • Eliminar la amistad en cualquier momento

Flujo completo

1. Buscar usuario

El usuario busca personas en la pestana "Buscar" usando el campo de texto. La busqueda es por nombre de usuario (minimo 2 caracteres).

Pestana Buscar → Escribir nombre → Resultados en vivo → Clic en "Agregar"

2. Enviar solicitud

Al hacer clic en "Agregar", se envia una solicitud de amistad. El sistema:

  • Crea un registro en la base de datos con estado pending
  • Notifica al destinatario por Socket.IO (en tiempo real si esta conectado)
  • Notifica por DM en Discord (si tiene cuenta vinculada)
  • Notifica por DM en Slack (si tiene cuenta vinculada)

3. Responder a la solicitud

El destinatario ve la solicitud en la pestana "Solicitudes" bajo la seccion "Recibidas". Puede:

  • Aceptar → se convierten en amigos
  • Rechazar → la solicitud se elimina
  • Cancelar (solo para quien la envio) → la solicitud se elimina

Los botones de aceptar/rechazar tambien aparecen como botones interactivos en los DM de Slack y Discord.

Plataformas donde se puede responder

Plataforma Enviar solicitud Aceptar / Rechazar
Web SlackBoard UI Si — pestana "Buscar" Si — pestana "Solicitudes"
Slack DM No Si — botones interactivos en el DM
Discord DM No Si — botones interactivos en el DM

Como funciona por detras

Modelo de datos

Cada solicitud es un documento Friendship en MongoDB:

CampoTipoDescripcion
userAObjectIdUsuario con ID menor (para evitar duplicados)
userBObjectIdUsuario con ID mayor
initiatorObjectIdQuien envio la solicitud
statusStringpending, accepted, o rejected

El par userA + userB tiene un indice unico, lo que garantiza que no puede haber dos solicitudes entre los mismos usuarios.

Indice unico compuesto

Para prevenir duplicados, se usa una funcion normalizePair que ordena los IDs:

function normalizePair(a, b) {
  return a < b ? { userA: a, userB: b } : { userA: b, userB: a };
}

Esto asegura que sin importar quien inicie la solicitud, el registro en la base de datos sea siempre el mismo.

API Endpoints REST

Metodo Endpoint Descripcion
GET /api/friendship/search?q= Buscar usuarios por nombre (minimo 2 caracteres)
GET /api/friendship/list Listar amigos aceptados
GET /api/friendship/pending Listar solicitudes pendientes (recibidas y enviadas)
POST /api/friendship/request Enviar solicitud de amistad (body: { to: userId })
PUT /api/friendship/accept/:id Aceptar solicitud pendiente
PUT /api/friendship/reject/:id Rechazar solicitud pendiente
DELETE /api/friendship/cancel/:id Cancelar/eliminar solicitud pendiente (iniciador o receptor)
DELETE /api/friendship/remove/:id Eliminar amigo aceptado

Notas importantes sobre la API

  • Aceptar/Rechazar son idempotentes: si la solicitud ya fue procesada (ej. via Slack/Discord), devuelven exito en vez de error.
  • Cancelar funciona para ambos usuarios: tanto el iniciador como el receptor pueden eliminar una solicitud pendiente.
  • El ID de la solicitud se obtiene del endpoint /pending, que devuelve los IDs en los campos received[].id y sent[].id.
  • Todos los endpoints requieren autenticacion (token JWT en header Authorization).

Notificaciones en tiempo real

Eventos Socket.IO

EventoDescripcionPayload
friendship:new-request Nueva solicitud recibida { friendshipId, from, fromUserId }
friendship:update Solicitud aceptada o rechazada { friendshipId, status }
friendship:removed Solicitud eliminada o amistad removida { friendshipId }

Todos los usuarios conectados a la sala user:{userId} reciben estos eventos. El badge de solicitudes en la sidebar se actualiza automaticamente.

Casos especiales

Envio de solicitud

  • No puedes enviarte una solicitud a ti mismo
  • No puedes enviar solicitud si ya son amigos
  • No puedes enviar solicitud si ya hay una pendiente
  • Si la solicitud fue rechazada, puedes reenviar una nueva

Aceptar / Rechazar

  • Solo el receptor puede aceptar o rechazar (el iniciador no puede aceptar su propia solicitud)
  • Si la solicitud ya fue procesada via Slack/Discord, el endpoint devolvia exito (idempotente)
  • Si la solicitud no existe o ya no esta pendiente, se devuelve error

Eliminar amistad

  • Cualquiera de los dos amigos puede eliminar la amistad
  • La eliminacion es inmediata y permanente
  • Pueden volver a enviarse una solicitud despues de eliminarse
